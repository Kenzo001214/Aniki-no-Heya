# Claude から Google ドライブに何ができるか（2026-08-25 実測）

「エージェントAIなら上書きできるのか？」を実際に試した結果。

## 結論：上書きだけはできない。それ以外はできる

| やりたいこと | 可否 | 使う仕組み |
|---|---|---|
| 中身を読む | ⭕️ | `read_file_content` / `download_file_content` |
| 新しいファイルを作る | ⭕️ | `create_file` |
| ゴミ箱に入れる | ⭕️ | `trash_file`（完全削除ではない。復元可能） |
| 名前を変える | ⭕️ | `update_file`（title） |
| 別フォルダへ移す | ⭕️ | `update_file`（parentId） |
| **中身を上書きする** | ❌ | **手段が用意されていない** |

`update_file` は名前と置き場所しか変えられない。**中身を差し替える口が存在しない**。
これは Claude Code（エージェント側）でも通常のチャットでも同じ。仕組みの制限であって、
AIの種類の違いではない。

だから更新は必ずこの形になる：

```
新しい内容で別名ファイルを作る → 旧ファイルをゴミ箱 or archive へ移す
```

> 補足：この部屋のセッションでは、ドライブのファイル移動が
> 権限チェックに引っかかって止まることがある。その場合は
> 「新規作成」までを Claude がやり、旧ファイルの退避は手作業で行う。

## 「データが増えると作り直しが大変」は half true

**マージ計算そのものは一瞬。** 66日分（10KB）で処理時間はミリ秒。
1000日分になっても Python なら誤差の範囲。ここは全く大変ではない。

**大変なのはアップロードの方。** ファイルを新規作成するとき、
中身を全部テキストとして送り出す必要がある。マスターが育つほどこの部分が重くなる。
チャットのAIが「作り直しが大変」と言っていたのは、実はここ
（会話の中に全文を書き出す＝長い・遅い・打ち間違いが混ざる）が理由。

Claude Code は計算をコードでやるので**間違いは混ざらないが、送信量の問題は残る**。

### 育ってきたときの逃げ道

1. 月1統合の運用を維持する（1回あたり数行の追加なら軽い）
2. マスターが数百KB規模になったら、`merge_masters.py` をローカル or
   GitHub Actions で回し、Drive API から直接書き込む方式に切り替える

## 検算の型（今回使ったもの）

統合後は必ずこの4点を機械で確認する。目視では見落とす。

- 既存行が**1セルも変わっていない**こと（旧マスターと差分比較）
- 追加行が差分ファイルと**完全一致**すること
- 日付が昇順・同一日付の重複なし（枝番は後のものを採用）
- 全行で `料金内訳の合計 == 料金合計列`

ツール：`tools/merge_stats.py`（この確認込みで動く）
