# Claude Code のこと

## どこで動いているのか

**自宅のPCではない。** Anthropic が用意したクラウド上の使い捨てサーバー。

Linux・4コア・メモリ15GB・タイムゾーンUTC。
セッションを開くとリポジトリが新しくクローンされ、
しばらく使わないと片付けられる。

→ **家のPCを切っても関係なく動く。** これが GitHub Actions と組み合わせたときの
最大の利点で、「PCを24時間つけっぱなしにする」必要がなくなる。

作業場所は消えるが、**`git push` した内容は GitHub に残る**ので損失はない。

## `CLAUDE.md` — 引き継ぎ書の代わり

チャットでは、話が長くなったら引き継ぎ書を作って新スレッドに渡していた。
Claude Code では**その手間が要らない**。

リポジトリの直下に `CLAUDE.md` を置いておくと、
**新しいセッションを開いた瞬間に自動で読まれる。**

- 毎回必要なことだけを書く（目安200行以内）
- 詳しい経緯は `HANDOVER.md` など別ファイルに置き、必要なときだけ読ませる

この二段構えにすると、セッションを分けるコストがほぼゼロになる。

## セッションの分け方

分ける単位は「ツール」ではなく**「リポジトリ」**。
セッションを開くとき、扱うリポジトリを選ぶ仕組みになっている。

チャットと違って「引き継ぎが面倒」という抵抗がないので、**気軽に分けてよい**。

## コンテキストの管理

| コマンド | できること |
|---|---|
| `/context` | いまどれだけ使っているか確認 |
| `/compact` | 会話を要約して圧縮。続きから作業できる |
| `/clear` | **Web版では使えない。** 新しいセッションを開くのが代わり |

## プランと料金

- Claude Code は **Pro でも Max でも使える**（研究プレビュー）。
  違いは機能ではなく**使える量**
- **チャットと Claude Code は共通の枠を使う。**
  Claude Code をたくさん使うと、普通のチャットの残量も減る
- **クラウドVMに別料金はかからない。** 手元のPCで動かしても安くならない
  （消費されるのはトークンであって、計算機の時間ではないため）

## データの扱い（仕事のデータを流すなら要確認）

Free / Pro / **Max** プランは、**データ利用の設定がオンだと会話が学習に使われる**。
Claude Code のセッションも対象。

| 設定 | 学習利用 | 保存期間 |
|---|---|---|
| オン | される | 5年 |
| オフ | されない | 30日 |

確認・変更: https://claude.ai/settings/data-privacy-controls
（設定変更は新しい会話・再開した会話から効く。過去分は遡らない）

**オーナーはオフに設定済み**（2026-08-25 確認）。
顧客の氏名・住所・電話を扱う仕事があるため、この状態を維持すること。

GitHub の Private リポジトリは公開されないが、**個人向け Copilot を使っている場合のみ**
作業中のコード断片が学習対象になりうる（2026-04-24 の規約変更）。Copilot 未使用なら無関係。

そもそも **顧客データは GitHub に置かない**方針。データは Drive にのみ流す。

## GitHub Actions と組み合わせる

「時間が来たら → 何かを取ってきて → 加工して → どこかへ送る」
という形のものは、だいたい同じ骨格で作れる。部品を差し替えるだけ。

覚えておくべき癖：

- cron の時刻は **UTC**。日本時間 −9時間で書く
- cron は **5〜20分遅れることがある**。余裕を持たせる
- **`Re-run failed jobs` は「その時のコミット」を再実行する。**
  コードを直したあとは必ず `Run workflow` で新規実行する
- テストするときは **ブランチを選んで** 実行する。main のままだと旧コードが動く

## ハマった実例

- **ntfy.sh は GitHub Actions と相性が悪い。**
  レート制限が**IP単位**で、Actions の共有ランナーは他人とIPを共有するため、
  自分の利用量に関係なく制限に引っかかる。構造的問題で設定では回避できない
  → Discord Webhook に移行して解決（制限はWebhook単位で約30件/分）
- **Discord は User-Agent を指定しないと403で弾かれる。**
  Python の urllib は既定で `Python-urllib/3.x` を名乗り、Cloudflare に拒否される
- **クラウドのサーバーは毎回まっさら。**
  「前回どこまでやったか」をファイルに保存していると、移植したとき毎回リセットされる。
  記録を GitHub にコミットして残す設計が必要
