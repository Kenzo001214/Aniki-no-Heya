# 自作HTMLツールの置き場所（tiiny.host からの移行）

対象: 「当日張り込みカルテ」のような、**CSV → Python → HTML1ファイル** で作るツール。

## まず整理: ホスティングは「配布」しかしていない

生成されたHTMLは**完全に自己完結**（外部通信ゼロ・データ埋め込み済み）。
つまりファイルさえ iPhone にあれば動く。
tiiny.host が解決していたのは「**どうやって iPhone にファイルを届けるか**」だけ。
→ 月額を払う価値があるかは、この一点だけで判断してよい。

## 重要な前提: GitHub は HTML を「表示」してくれない

`raw.githubusercontent.com` は HTML を **text/plain（ただの文字）** として返す。
Private / Public を問わず、ブラウザで開いてもソースが見えるだけで動かない。
**HTMLを動く形で配信する機能は GitHub Pages だけ**で、それは常に全世界公開。
→ 業務データ入りのこのツールは Pages に置けない（`git-github.md` 参照）。

## 推奨: Private リポジトリ + Actions + ダウンロードして開く

1. Private リポジトリに **Python スクリプトと CSV** を置く
2. GitHub Actions で生成（`workflow_dispatch` = ボタン手動実行でよい）
3. 生成された HTML を**リポジトリにコミットさせる**
4. iPhone の Safari で GitHub を開き、そのファイルの
   **「Download raw file」**（ダウンロードアイコン）をタップ
5. Safari の**ダウンロード一覧（↓）からタップして開く**と JavaScript ごと動く

- 費用ゼロ / データは Private のまま外に出ない
- 過去バージョンが全部コミット履歴に残る（tiiny.host にはない利点）
- 注意: ファイルアプリのプレビューだと動かないことがある。Safari のダウンロード一覧か
  **Documents（Readdle社・無料）**アプリから開く

## 代替: Pyto でその場生成

Python が iPhone 内（Pyto）で完結するなら、**転送すら不要**。
生成 → ファイルアプリに保存 → 開く、で終わり。ネットも要らない。
CSV を手で書き集めている運用なら、こちらのほうが手数が少ないこともある。

## Actions のアーティファクトは使わない

Actions の「artifact」機能でも受け取れるが、**zip で降ってくる**ので
iPhone で解凍する手間が増える（ファイルアプリで長押し→展開）。
リポジトリに直接コミットさせるほうが早い。

# 重要: HTMLツールには「2種類」ある

置き場所の正解は**タイプによって真逆になる**。まずどちらか見極める。

| | **A. データ埋め込み型** | **B. データ書き込み型** |
|---|---|---|
| 例 | 当日張り込みカルテ | 先生の最優先メモ |
| 作り方 | Python が数字ごとHTMLに焼く | 空のアプリ。使う人が入力する |
| データの居場所 | **ファイルの中** | **ブラウザの中（localStorage）** |
| ファイル単体を人に渡すと | **業務データごと渡る** | 空のアプリが渡るだけ |
| ローカルで開く（file://） | ✓ 動く | **✗ 壊れる** |
| 正解の置き場所 | iPhone内 / Private リポジトリ | **GitHub Pages** |

## なぜ B はローカルファイルだと壊れるのか

**Safari は `file://` で開いたページに localStorage を使わせない**（セキュリティ上、
ローカルファイルは「どこの誰のページか」を特定できない＝オリジンが無いため）。

エラーで JavaScript が止まるので、画面は出るのに**ボタンが全部効かない**という
分かりにくい壊れ方をする。マイク（音声入力）も同じ理由で https:// が必要。

→ **B タイプは「ちゃんとした URL」がないと成立しない。**

## B タイプを GitHub Pages に置いてよい理由

**HTMLファイルの中にデータが入っていない**から。
入力された内容は各自の iPhone の中だけに保存され、GitHub には一切送られない。
公開されるのは「空のアプリ」だけ。他人がURLを開いても、その人の空の画面が出るだけ。

## B タイプの2つの落とし穴

### 1. データは URL に紐づく（引っ越すと消える）
localStorage は「そのURL専用の保存箱」。**別のURLに移ると中身は引き継がれない。**
tiiny.host から移す前に「📋 まとめをコピー」で中身を退避しておくこと。

### 2. 7日使わないと Safari がデータを消す
Safari には「**7日間アクセスがないサイトの保存データを自動削除する**」仕組みがある
（トラッキング対策。ITP と呼ばれる）。週1回しか使わないメモだと消えかねない。

→ **対策: Safari の共有ボタンから「ホーム画面に追加」する。**
ホーム画面のアプリは Safari 本体とは別扱いになり、**この7日ルールの対象外**になる。
B タイプでは追加は「見た目のため」ではなく**データを守るために必須**。

## B タイプの手順（iPhone / Safari）

1. https://github.com/new でリポジトリ作成。**Public** を選ぶ（無料 Pages の条件）
2. `Add file` → `Create new file` → ファイル名を **`index.html`** にする
3. HTMLの中身を**コピペ**（手打ちはスマート引用符で壊れる）→ `Commit changes`
4. `Settings` → `Pages` → Source を `Deploy from a branch`、Branch を `main / (root)` → `Save`
5. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける
6. Safari で開き、**共有 → ホーム画面に追加**

出典:
- https://webkit.org/tracking-prevention/
- https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage

# B タイプと「個人情報」— よくある誤解

## 事実: B タイプのHTMLファイルに個人情報は入っていない

「先生の最優先メモ」で言えば、**個人情報は入力された内容**であって、
それは **iPhone の Safari の中（localStorage）にしか無い**。

- HTMLファイル自体は**空のフォーム**。何度ダウンロードしても中身は空
- **tiiny.host のサーバーにも上がっていない。** tiiny は空のアプリを配っているだけ
- 入力内容がネットに出る処理は、このアプリのコードのどこにも無い（送信先ゼロ）

→ **GitHub Pages に置いても個人情報は公開されない。** 公開されるのは空のフォーム。

ただし「それでも公開URLは避けたい」は判断として正当（URLを知られたら
他人も同じ入力画面を使える、アプリの存在自体を知られる、等）。その場合は下記。

## 公開せずに使う3つの方法

| | A. 鍵付きURL | B. アプリを改造 | C. iPhone内サーバー |
|---|---|---|---|
| 中身 | Cloudflare Pages + Access | 保存方式を作り変える | WorldWideWeb 等のアプリ |
| 費用 | 無料（50人まで） | 無料 | 無料（アプリ内課金あり） |
| アプリの改造 | **不要** | 必要 | **不要** |
| 使い勝手 | いまと全く同じ | 保存/読込が手動に | 毎回サーバー起動が必要 |
| ネット | 必要 | **不要** | 不要 |
| 7日で消える問題 | ホーム画面追加で回避 | **無関係（消えない）** | 起動のたび別扱いの恐れ |

### A. Cloudflare Pages + Cloudflare Access（推奨）
静的サイトを無料で置ける Cloudflare Pages に、無料の認証機能 Access を被せる。
**指定したメールアドレスの本人しか開けないURL**になる。
tiiny.host が有料でやっているパスワード保護と同じことが無料でできる。
HTTPS なので localStorage も音声入力もそのまま動く＝**アプリは1行も直さなくていい**。
初回設定だけやや手間（Cloudflareアカウント作成 → Pages にデプロイ → Zero Trust で Access 設定）。

### B. アプリを改造して完全オフライン化
**`file://` ではブラウザの自動保存が一切使えない**（localStorage も IndexedDB も
Cookie も全部ダメ。オリジンが無いため）。なので**保存方式そのものを変える**必要がある:

- 入力中はメモリ上に持つ
- 「保存」ボタン → JSONファイルとして書き出し、「ファイル」アプリに置く
- 開いたら「読み込み」ボタンでそのファイルを選ぶ

得るもの: 完全オフライン / 7日削除の心配なし / iCloud でバックアップ・世代管理できる
失うもの: 自動保存。**閉じる前に保存を忘れると消える**
注意: 音声入力ボタンは file:// では動かない（マイクは HTTPS 必須）。
iPhone キーボードのマイク入力で代替する。

### C. iPhone内でローカルサーバー
**WorldWideWeb – Mobile**（Iconfactory・無料）等でフォルダを配信し、
`http://localhost:8080/` で開く。localhost は「ちゃんとしたURL」扱いなので
**localStorage も音声入力も動く＝改造不要**。
難点: 使うたびにサーバーアプリを起動する必要がある。人に渡すツールには向かない。

出典:
- https://www.cloudflare.com/plans/free/
- https://iconfactory.com/worldwideweb/
