# Git と GitHub

## 用語

| 言葉 | 意味 |
|---|---|
| **リポジトリ** | プロジェクト1個分の箱。フォルダ + その変更履歴 |
| **コミット** | セーブ。上書きではなく積み重なるので、過去のどの時点にも戻れる |
| **ブランチ** | 作業用の枝分かれ。本番に触らずに試せる |
| **マージ** | 枝で試したものを本番に合流させる |
| **プッシュ** | 手元の変更を GitHub 側へ送る |
| **`.gitignore`** | 「これは GitHub に上げない」というリスト |

## データは消えない

放置してもリポジトリは消えない。期限もない。**押し入れは無期限。**

消えるのは Claude Code の作業場所（クラウドVM）だけで、
`git push` した時点で中身は GitHub 側に残っている。

**例外がひとつ**: 60日間コミットがないと、GitHub が
**スケジュール実行（Actions の定期実行）を自動停止する**。
データが消えるのではなく、自動実行のスイッチが切られるだけ。
→ 月1回の空コミットを自動で積む `keepalive.yml` で対策できる。

## 無料枠（2026年8月時点）

| 項目 | 無料枠 |
|---|---|
| リポジトリ数 | 無制限（Private も） |
| 1リポジトリの容量 | 推奨1GB / 5GB以内を強く推奨 |
| 1ファイル | 100MB上限（50MBで警告） |
| Actions 実行時間 | **月2,000分**（Private のみ。Public は無制限） |

1GB をテキストで埋めるには文庫本3,000冊分が必要。
**文字とコードだけなら実質無制限。** 気にすべきは写真・動画を置き始めたときだけ。

実際に効いてくるのは Actions の2,000分のほう。
1日1回・3分の処理なら月90分なので、同規模のツールを20個は動かせる。

## 削除と改名

**削除**: Settings の最下部 → `Delete this repository`。
確認欄には**ユーザー名込みのフルネーム**を入れる（例: `Kenzo001214/repo-name`）。
リポジトリ名だけでは通らない。

削除しても**90日以内なら復元できる**（フォークされていない場合）。
→ https://docs.github.com/en/repositories/creating-and-managing-repositories/restoring-a-deleted-repository

**改名**: Settings の最上部 → `Repository name` を書き換えて `Rename`。
確認ダイアログなし、即完了。何度でもやり直せる。

改名すると**旧URLから新URLへ自動で転送が張られる**ので、リンクは切れない。
削除にはこの転送がない。これが両者の決定的な違い。
（ただし手元にクローンがある場合は `git remote set-url` で直しておくのが安全）

## 秘密情報の扱い

APIキー・トークン・Webhook URL は**パスワードと同じ**。

- コードに直接書かない。**環境変数から読む**
- GitHub の **Secrets** に登録する（Settings → Secrets and variables → Actions）
- Claude はSecretsの値を読めないし、**チャットに貼ってもいけない**
- `.env` などは `.gitignore` で除外する
- **`.gitignore` は最初のコミットから入れる。** 後から足しても、
  過去のコミットに残った分は消えない

万一漏らしても、**キーを再発行すれば古いものは無効になる**ので復旧はできる。

## GitHub Pages（無料のWebサイト公開）

GitHub には **Pages** という機能があり、リポジトリに置いた
HTML/CSS/JavaScript をそのまま Web サイトとして**無料公開**できる。

- URL は `https://kenzo001214.github.io/リポジトリ名/` になる
- 設定は Settings → Pages → Branch を選んで Save するだけ
- ファイルを push（Safari で編集して Commit）するたびに自動で反映される

**向いているもの**: tiiny.host に置くような「HTMLファイル一式」のアプリ。
ブラウザの中だけで完結するもの（＝静的サイト）なら、ほぼそのまま引っ越せる。

**注意点**:
- 無料で使えるのは **Public（公開）リポジトリのみ**。コードも誰でも見られる
- **パスワード保護はできない**（URLを知らなければまず辿り着けないが、秘密ではない）
- ⚠️ **有料プランで Private リポジトリから Pages を使っても、
  公開されるサイト自体は誰でも見られる**（隠せるのはリポジトリの中身だけ）。
  閲覧制限付きのサイトは Enterprise という法人プランでしか作れない
- サーバー側の処理（データ保存、ログイン等）が必要なアプリは Pages 単体では不可
- → **業務データ・個人情報を含むページは Pages に置かない。**
  自己完結型のHTMLなら iPhone 内で直接開く運用ができる（下記）

## 自己完結型HTMLを iPhone 内で運用する

外部読み込みのない1ファイル完結のHTML（データ埋め込み型）は、
**ホスティング不要で iPhone の中だけで動かせる**。データが外に出ないので
業務データ入りのツールに向く。

1. **Safari で**ファイルをダウンロードする（この手順が必須。詳細は `html-tool運用.md`）
2. Safari の**ダウンロード一覧からタップ**して開く → JavaScript が動く
3. ⚠️ **「ファイル」アプリから開いてはいけない。**
   iOS のプレビュー（Quick Look）は **JavaScript を必ず削除する**ので、
   画面は出るがボタンが一切効かない

更新は「新しいファイルを保存し直す」だけ。バージョンの保管場所として
**Private リポジトリに置いておく**のは安全で相性が良い（Pages を有効にしなければ公開されない）。

## iPhone で作業するときの罠

- **編集は GitHub アプリではなく Safari。** アプリは機能が制限されている
- **ファイルのアップロードは使わない。** ファイル名が化ける
  （実例: `check_stock.py` が `check stock .py` になった）
- **フォルダは先に作れない。** ファイル名欄に `a/b/c.yml` とスラッシュ込みで
  打つと自動で作られる
- **コードは必ずコピペ。** 手打ちすると **スマート引用符** で
  `"` が `“` に化けて壊れる（実例: 2026年4月の在庫チェッカーはこれで動かなかった）
